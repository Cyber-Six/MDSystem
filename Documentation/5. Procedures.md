# 5. Procedures

## 5.1 Development Environment Setup

### 5.1.1 Prerequisites Installation

1. **Install Node.js 18+ LTS** from [nodejs.org](https://nodejs.org) or via `nvm`:
   ```bash
   nvm install 18
   nvm use 18
   ```

2. **Install PostgreSQL 15+** and create the MDSystem database:
   ```bash
   sudo apt install postgresql postgresql-contrib
   sudo -u postgres createdb mdsystem
   sudo -u postgres psql -d mdsystem -f Backend/config/data/post_build_setup.sql
   ```

3. **Install Redis 7+** for session storage, caching, and job queues:
   ```bash
   sudo apt install redis-server
   sudo systemctl enable redis-server
   ```

4. **Install Expo CLI** for mobile development:
   ```bash
   npm install -g expo-cli eas-cli
   ```

### 5.1.2 Backend Configuration

1. Create a `.env` file in `Backend/` with the following environment variables:
   ```env
   # Server Ports
   PATIENT_PORT=3000
   MEDICAL_PORT=3001
   
   # PostgreSQL
   DB_HOST=localhost
   DB_PORT=5432
   DB_NAME=mdsystem
   DB_USER=postgres
   DB_PASSWORD=<secure_password>
   
   # Redis
   REDIS_HOST=localhost
   REDIS_PORT=6379
   
   # JWT
   JWT_SECRET=<64_char_hex_secret>
   JWT_REFRESH_SECRET=<64_char_hex_secret>
   
   # TOTP Encryption
   TOTP_ENCRYPTION_KEY=<64_char_hex_key>
   
   # Email (SMTP)
   EMAIL_HOST=smtp.gmail.com
   EMAIL_PORT=587
   EMAIL_USER=<email>
   EMAIL_PASSWORD=<app_password>
   
   # Google OAuth
   GOOGLE_CLIENT_ID=<client_id>
   
   # reCAPTCHA
   RECAPTCHA_SECRET_KEY=<secret_key>
   RECAPTCHA_MOBILE_SECRET=<shared_secret>
   
   # WHO ICD API
   ICD_CLIENT_ID=<who_client_id>
   ICD_CLIENT_SECRET=<who_client_secret>
   
   # Chatbot
   CHATBOT_URL=<fastapi_chatbot_url>
   CHATBOT_API_KEY=<api_key>
   
   # Expo Push
   EXPO_ACCESS_TOKEN=<expo_token>
   ```

2. Install backend dependencies:
   ```bash
   cd Backend && npm install
   ```

3. Start the patient server:
   ```bash
   npm run start:patient   # Starts server.js on port 3000
   ```

4. Start the staff server (separate terminal):
   ```bash
   npm run start:staff     # Starts staff.js on port 3001
   ```

### 5.1.3 Web Portal Setup

1. Install shared core package dependencies:
   ```bash
   cd packages/core && npm install
   ```

2. Install and start the patient portal:
   ```bash
   cd mds-patient && npm install && npm run dev
   ```
   The Vite dev server proxies 6+ API path prefixes (`/auth`, `/emr`, `/patient`, `/info`, `/econsultation`, `/socket.io`) to the backend.

3. Install and start the staff portal (separate terminal):
   ```bash
   cd mds-staff && npm install && npm run dev
   ```
   The Vite dev server proxies 18+ API path prefixes to the staff backend server.

### 5.1.4 Mobile Application Setup

1. Install mobile dependencies:
   ```bash
   cd mds-mobile && npm install
   ```

2. Configure the API URL in environment:
   ```bash
   export EXPO_PUBLIC_API_URL=http://<local_ip>:3000
   ```

3. Start the Expo development server:
   ```bash
   npx expo start
   ```

4. Connect via Expo Go app on physical device or start Android/iOS emulator.

## 5.2 Backend Development Procedures

### 5.2.1 Adding a New GraphQL Module

1. **Create schema**: Define `.graphql` schema file in the route module directory with `type Query`, `type Mutation`, and custom type definitions.

2. **Create resolvers**: Implement resolver functions in a `resolvers/` subdirectory, organized by role (patient vs. medical).

3. **Register endpoint**: In the server entry point, mount the GraphQL endpoint using `express-graphql` with the merged schema and resolver map:
   ```javascript
   const { makeExecutableSchema } = require('@graphql-tools/schema');
   const schema = makeExecutableSchema({ typeDefs, resolvers });
   app.use('/module/role', jwtProtect('role'), graphqlHTTP({ schema }));
   ```

4. **Add middleware**: Apply `jwtProtect(role)` for authentication, plus any additional middleware (rate limiting, credential status checks).

### 5.2.2 Adding a New REST Endpoint

1. Create a new Express Router in the appropriate `routes/` subdirectory.
2. Define route handlers with `Joi` schema validation for request bodies.
3. Apply middleware chain: `jwtProtect(role)` → `ipRateLimiter(profile)` → handler.
4. Mount the router in `server.js` (patient routes) or `staff.js` (staff routes), or both.

### 5.2.3 Database Migration Procedure

1. Write the SQL migration in `Backend/config/data/` or as a standalone `.sql` file.
2. Test the migration against a development database copy.
3. Apply the migration:
   ```bash
   psql -d mdsystem -f migration.sql
   ```
4. Update the `post_build_setup.sql` if the change affects the initial schema.

### 5.2.4 Adding a New Permission Key

1. Define the new key in `Backend/services/permit.js` within the appropriate module section.
2. Add the corresponding entry to `mds-staff/src/modules/role-management/role-permissions.js`:
   - Add to `MODULE_PERMISSION_MAP` under the relevant module.
   - Add a human-readable label to `PERMISSION_KEY_LABELS`.
3. Insert the new permission key into the `rolesTable` database table.
4. Gate the relevant backend route or resolver behind the new permission check.
5. Gate the relevant frontend component or route behind `usePermissions().hasPermission()`.

## 5.3 Frontend Development Procedures

### 5.3.1 Creating a New Staff Module

1. **Create module directory** under `mds-staff/src/modules/<module-name>/`.
2. **Create service file**: Implement GraphQL or REST API calls using the shared `axiosRequest` instance.
3. **Create view component**: Build the main page component with Tailwind CSS styling.
4. **Register route**: Add a lazy-loaded route in `Dashboard.jsx` wrapped in `<PermissionRoute moduleId="...">`.
5. **Add sidebar entry**: Register the navigation item in `StaffSidebar.jsx` with the appropriate permission gate and icon.
6. **Add socket events** (if real-time): Register event handlers in `StaffNotificationProvider`.

### 5.3.2 Creating a New Patient Module

1. **Create module directory** under `mds-patient/src/modules/<module-name>/`.
2. **Create service file** using GraphQL or REST via `axiosRequest`.
3. **Create view component** with Tailwind CSS styling.
4. **Register route**: Add a lazy-loaded route in `Dashboard.jsx`.
5. **Add sidebar entry** in the patient layout sidebar.

### 5.3.3 Creating a New Mobile Screen

1. **Create screen component** under `mds-mobile/src/screens/<module>/`.
2. **Add navigation type** in `mds-mobile/src/navigation/types.ts`.
3. **Register in navigator**: Add the screen to the appropriate navigator (MainTabNavigator or MoreStackNavigator).
4. **Apply record gate** if the screen requires initial record completion via `PendingRecordGate`.
5. **Create service** in `mds-mobile/src/services/` using the GraphQL client.

## 5.4 Deployment Procedures

### 5.4.1 Production Build

1. **Build web portals:**
   ```bash
   cd mds-patient && npm run build    # Outputs to mds-patient/dist/
   cd mds-staff && npm run build      # Outputs to mds-staff/dist/
   ```

2. **Configure backend for production:**
   - Set `NODE_ENV=production`
   - Ensure `server.js` serves `mds-patient/dist/` as static files
   - Ensure `staff.js` serves `mds-staff/dist/` as static files

3. **Build mobile app:**
   ```bash
   cd mds-mobile
   eas build --platform android --profile production
   eas build --platform ios --profile production
   ```

### 5.4.2 Server Deployment (Raspberry Pi 5)

1. Transfer the application files to the Raspberry Pi.
2. Install Node.js 18+, PostgreSQL 15+, and Redis 7+.
3. Restore the PostgreSQL database from the setup SQL.
4. Configure environment variables in `.env`.
5. Start both backend servers using a process manager (e.g., PM2):
   ```bash
   pm2 start Backend/server.js --name mds-patient-api
   pm2 start Backend/staff.js --name mds-staff-api
   pm2 save
   pm2 startup
   ```
6. Configure the domain DNS to point `www.mdsystemtip.space` to the server IP and `staff.mdsystemtip.space` to the same IP.
7. Set up a reverse proxy (Nginx or Caddy) to route:
   - `www.*` → port 3000 (patient server)
   - `staff.*` → port 3001 (staff server)
8. Install SSL certificates via Let's Encrypt / Certbot.

### 5.4.3 Database Backup Procedure

1. Schedule daily PostgreSQL backups:
   ```bash
   pg_dump mdsystem > /backup/mdsystem_$(date +%Y%m%d).sql
   ```
2. Rotate backups (retain 30 days).
3. Copy backups to the optional external 4TB HDD.
4. Test restore periodically:
   ```bash
   psql -d mdsystem_test < /backup/mdsystem_YYYYMMDD.sql
   ```
