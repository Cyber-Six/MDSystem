# 1. Objective(s)

## 1.1 General Objective

To design, develop, and deploy a comprehensive, web-based and mobile-accessible Electronic Medical Record (EMR) system — the **Medical and Dental Record Management System (MDSystem)** — for the Medical-Dental Services (MDS) of the Technological Institute of the Philippines (TIP), replacing the existing manual, paper-based workflow with a centralized digital platform that ensures operational efficiency, data integrity, regulatory compliance, and secure management of student and employee health records across multiple campus locations.

## 1.2 Specific Objectives

1. **To digitize and centralize medical and dental records** by implementing a PostgreSQL-backed data layer with over 60 relational tables, 40+ enumerated types, and polymorphic profile models (Student, Employee, Superior) that store the complete longitudinal health history of patients — including vital signs, medical history, dental charting, allergies, immunizations, lifestyle assessments, OB-GYN records, and emergency contacts — organized by academic semester and accessible in real time by authorized clinic personnel.

2. **To establish a role-based access control (RBAC) and multi-factor authentication (MFA) security framework** by implementing a JWT dual-token architecture (access + refresh tokens with Redis-backed session anchoring), adaptive reCAPTCHA v2, RFC 6238–compliant TOTP two-factor authentication with AES-256 encrypted secrets, Google OAuth restricted to the institutional `@tip.edu.ph` domain, progressive login lockout with cryptographic timing-attack resistance, IP-based rate limiting, and a granular permission system comprising 40+ permission keys across 11 functional modules — ensuring strict compliance with the Philippine Data Privacy Act of 2012 (R.A. 10173).

3. **To provide a staff-facing web portal (`mds-staff`)** built on React 19, Vite 7, and Tailwind CSS 3, featuring a permission-gated dashboard with real-time statistics, patient search with a browser-style multi-tab record viewer (supporting 14+ simultaneous sub-queries per patient), a complete consultation workflow with ICD-10/ICD-11 diagnosis coding (backed by WHO API integration with local caching), medical and dental record approval pipelines (Pending → Revision → Approved/Rejected), interactive dental charting with 13 tooth condition legends, a Messenger-style health chat interface with Socket.IO-driven real-time messaging, and comprehensive analytics with 30+ configurable report queries exportable as PDF, Excel, and CSV.

4. **To provide a patient-facing web portal (`mds-patient`)** built on React 19, Vite 7, and Tailwind CSS 3, enabling students and employees to submit initial and updated medical/dental records through multi-step guided forms, schedule appointments via a dynamic slot-based booking system with morning/afternoon sessions and configurable capacity per campus location (Arlegui, Casal, Quezon City), request medicines from clinic inventory, participate in real-time e-consultations via the ticketed health chat system, view and download generated documents (prescriptions, medical certificates, diagnosis reports), and manage account security settings including password changes and TOTP 2FA enrollment.

5. **To develop a cross-platform mobile application (`mds-mobile`)** using Expo SDK 54, React Native 0.81, and TypeScript, with NativeWind/Tailwind CSS styling and React Navigation 7, delivering the full patient experience — authentication, multi-step record forms with catalog search, appointment booking, real-time health chat with local push notifications (Expo Notifications with Android HIGH-importance channel), medicine requests, document downloads (via `expo-sharing`), and announcements — while maintaining feature parity with the web portal through the shared `@mdsystem/core` package.

6. **To architect a platform-agnostic shared business logic layer (`@mdsystem/core`)** as an ESM JavaScript package using a factory-based dependency injection pattern, providing token management (with namespace isolation for multi-portal localStorage/AsyncStorage), an Axios request handler with automatic 401 retry and request queuing to prevent thundering-herd token refresh, a Socket.IO client wrapper, institutional email validation (student/employee/medical pattern detection), password validation, and role detection — enabling code reuse across the web portals and React Native mobile app without platform coupling.

7. **To implement a real-time notification and communication infrastructure** using Socket.IO with a Redis adapter for cross-server fan-out (patient server on port 3000, staff server on port 3001), supporting per-user rooms, role-based broadcasts, branch-scoped event channels, a Redis-backed offline notification queue with atomic flush, and Expo push notification integration for mobile users — ensuring that appointment updates, medicine request status changes, EMR approval events, health chat messages, document submission alerts, and administrative announcements are delivered instantly regardless of client platform.

8. **To implement a medical inventory management system** with batch-level tracking (batch numbers, expiry dates, supplier records, location-aware stock), a patient medicine request workflow (Pending → Approved → Completed with stock reservation on approval), direct dispensing capabilities, supply splitting across locations, manual stock adjustments with audit trails, prescription issuance linked to consultation outcomes, and automated low-stock and near-expiry alerting — providing the clinic with complete visibility into pharmaceutical and supply resource utilization.

9. **To deliver a dynamic analytics and reporting engine** with 30+ pre-built statistical queries spanning consultations (by type, mode, and temporal trends), top ICD-10 diagnoses, vital sign distributions (BMI, blood pressure), appointment utilization, immunization coverage, dental procedure frequencies, lifestyle risk assessments, allergy epidemiology, and demographic cross-tabulations — with configurable date ranges, period aggregations (daily through annual), branch filtering, and multi-format export (PDF via PDFKit with Chart.js-rendered visualizations, Excel via ExcelJS, and CSV) to support institutional reporting requirements including DOLE annual health reports.

10. **To implement a document generation and management subsystem** supporting tag-based document templates (Medical Certificate, Prescription, Diagnosis Report, Staff Report), a patient document request and approval workflow (Requested → Pending → Recorded → Archived), file uploads with magic-byte validation (JPEG, PNG, WebP, PDF, MP4, MOV), a staging area with Redis-tracked per-user file counts, and secure file serving with path traversal protection — enabling the clinic to transition from manual paper-based certificate and prescription issuance to a fully digital document lifecycle.

11. **To ensure reliable background processing and communication** through BullMQ job queues backed by Redis for asynchronous email delivery (verification codes, 2FA OTPs, password resets, notification emails) via SMTP with 5-retry exponential backoff, daily rotating Winston log files for operational auditing, and a chatbot proxy middleware enabling SSE-streamed AI-assisted e-consultations through an external FastAPI-based microservice with service-to-service API key authentication.
